# Two PaddleOCR engines on one L4

The existing NVIDIA device plugin v0.14.5 supports node-selected time-slicing configurations. `nvidia-timeslicing-values.json` supplies an exclusive default and a `paddle-two` configuration advertising two `nvidia.com/gpu` slots per physical GPU. Each pod requests exactly one slot. This shares execution and VRAM; it does not enforce a half-memory allocation or provide MIG/MPS isolation.

Merge these values with the existing `nvdp` Helm release values; retain its affinity, tolerations, and pinned version. Label the target existing node `nvidia.com/device-plugin.config=paddle-two`. The NodePool merge patch adds the same label for future nodes. Existing nodes do not acquire NodePool template labels retroactively. No new NodeClaim is needed to enable sharing on an existing GPU. Template changes may mark existing NodeClaims drifted: preserve the benchmark node with disruption budgets and `karpenter.sh/do-not-disrupt` while testing.

`../charts/paddleocr-vl-hps/values-timeslicing-l4.json` configures two stock-vLLM pods, one Triton pipeline worker per pod, and one scheduled GPU slot per pod. Each vLLM engine budgets 28% of physical GPU memory; layout predictor allocations consume additional VRAM outside that budget. The benchmark initially uses two releases to control startup order and route requests deterministically, but both use real device-plugin allocations. Start engine pods sequentially: concurrent initialization can distort vLLM memory profiling. The values file alone does not serialize initial startup of two replicas.

For a controlled one-node test, additionally select the preserved node hostname. Without that selector, the scheduler may distribute pods across eligible nodes. Verify both pods' nodeName and GPU UUID, node allocatable GPU count of two, and a GPU limit of one on each VLM container.

The completed L4 comparison found two active engines slower: about 26% lower direct-crop throughput and 20–30% lower end-to-end throughput. The active original node and NodePool were returned to `exclusive` (one schedulable GPU); the `paddle-two` configuration remains available for explicitly selected future tests. See `../benchmarks/2026-09-16/DIAGNOSTIC_RESULTS.md`. L40S sharing remains unmeasured because the on-demand launches exceeded the GPU vCPU quota and the bounded Spot attempt could not obtain capacity. Saved pre-change device-plugin values and node/pool snapshots are in `../benchmarks/2026-09-16/`. Do not reduce advertised slots while both engine pods still hold allocations. Restore or consolidate benchmark releases before reverting sharing.
